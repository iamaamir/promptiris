# Decision register

This register is the exhaustive checkpoint for the initial design grill and the implementation-governance continuation. “Accepted” means agreed for the current design baseline; it may still be superseded through a later documented decision. ADR links identify the smaller subset of decisions whose trade-offs are costly and non-obvious.

| 49 | Accepted | Use one polyglot monorepo; Go CLI is a protocol client of the Node runtime, never a second Kernel; share schemas and conformance fixtures. See [ADR-0002](./adr/0002-one-kernel-runtime-neutral-protocol.md) and [ADR-0006](./adr/0006-polyglot-monorepo-and-official-adapters.md). |
| 50 | Accepted | Ship the official Pi adapter in v1 and keep future Codex/OpenCode adapters in the same repository; adapters remain thin and capability-honest. |
| 51 | Accepted | Default Enhance normalizes, capability-adapts, invokes one versioned neutral strategy, decodes, validates, optionally target-adapts, and renders; bounded parsing fallback never triggers a second call. |
| 52 | Accepted | Recipe Overlay extends at most one base using exact add/replace/remove/configure operations and reusable fragments; compilation flattens and validates the graph. |
| 53 | Accepted | Human config is JSONC, lockfile is strict JSON, no executable config in v1; SDK accepts objects and Hosts may parse native formats. |
| 54 | Accepted | Use JSON-RPC 2.0 with Content-Length-framed UTF-8 stdio, mandatory initialize/negotiation, protocol-only stdout, no batch v1, and separate runtime versus Plugin method surfaces. |
| 55 | Accepted | Use JSON Schema 2020-12 with a constrained portable profile and strict, non-mutating validation; accept a Go binding generator only after it passes the shared conformance fixtures, with schemas remaining authoritative. |
| 56 | Accepted | Model Run outcomes as success/degraded/blocked/cancelled/failed and original/transformed origin; return operational outcomes as Results and reserve protocol errors for protocol faults. |
| 57 | Accepted | Transfer failures as safe Diagnostics, keep richer Debug Records ephemeral and opt-in, register/validate namespaced Plugin codes, normalize unexpected exceptions, and isolate observer/debug persistence. See [ADR-0007](./adr/0007-errors-are-data-debug-records-are-ephemeral.md). |
| 58 | Accepted | Fix protocol v1 to six public phases—`preflight`, `analyze`, `transform`, `adapt`, `validate`, and `render`—with known execution semantics. | 59 | Accepted | Make `PromptDocument` text-first and separate user `content` from Host-supplied `context`. | 60 | Accepted | Use a typed, atomic, revision-aware Meta Prompt Patch protocol rather than arbitrary JSON Patch or shared mutation. See [ADR-0010](./adr/0010-typed-atomic-domain-patches.md). |
| 61 | Accepted | Reserve `Protected Span` for exact Kernel-enforced textual invariants. Represent meaning-level requirements as immutable Semantic Constraints evaluated by Guard Plugins during `validate`; the Kernel never claims semantic preservation from textual checks alone. See [ADR-0011](./adr/0011-separate-exact-protection-from-semantic-validation.md). |
| 62 | Accepted | Use one revision-bound `TextSelector` for text Patches and Protected Spans: stable block ID, zero-based half-open Unicode-code-point range, exact quote, optional prefix/suffix evidence, and grapheme-boundary validation. | 63 | Accepted | Make Artifacts immutable, Kernel-identified envelopes with namespaced semantic kind, media type, optional data schema/digest, JSON or Resource Reference value, classification, and compact provenance. | 64 | Accepted | Use a stable `RunResult` envelope containing status, locked Recipe reference, optional primary/origin, declared alternatives/exposed Artifacts, assumptions, clarifications, safe Diagnostics, and bounded summary. | 65 | Accepted | Standardize one Kernel-stamped Event envelope and a bounded v1 catalog for Run, Phase, Plugin, Provider, Patch, Guard, outcome, and observer lifecycle. | 66 | Accepted | Standardize a safe Diagnostic envelope, thirteen broad routing categories, namespaced registered codes, structured retry advice, causal references, and a deliberately small initial core code catalog. Hosts branch on codes; exception/debug data remains separate. |
| 67 | Accepted | Define a concrete native-Plugin supervisor profile: bounded headers/frames/nesting/artifacts/events/diagnostics/debug/stderr, single invocation by default with negotiated tested concurrency, fixed handshake/cancel/shutdown grace periods, no retry of interrupted work, lazy restart, and crash-loop quarantine. | 69 | Accepted | Give Plugins plain immutable resolved configuration and retain a separate immutable `ConfigTrace` indexed by JSON Pointer. | 70 | Accepted | Make the bundled OpenAI-compatible Provider's portable baseline only non-streaming text generation through Chat Completions with `model`, one textual user message, and an output-token bound. | 71 | Accepted | Gate each Default Enhance strategy release on a versioned 400-case transformation corpus and a 160-case paired downstream suite. | 72 | Accepted | Implement the official Pi Adapter on Pi's asynchronous `input` transform hook. | 73 | Accepted | Distribute the Go CLI and canonical Node runtime as one versioned adjacent-runtime bundle: native Go launcher, private pinned Node LTS executable, compiled runtime, schemas/assets/licenses, and a hashed manifest. | 74 | Accepted | Build the canonical runtime as strict ESM TypeScript on the latest LTS Node line pinned at implementation/release time, in a pnpm workspace with `tsc` project references, esbuild runtime bundling, Vitest projects, Ajv, and direct workspace scripts; build the Go CLI with a supported stable Go toolchain, standard library by default, Cobra for commands, and the selected Go schema validator. | 75 | Accepted | Version every public npm package with SemVer, the wire protocol and schemas independently, and Recipe/strategy assets by version plus digest. | 76 | Accepted | Use Apache-2.0 for the project and DCO 1.1 sign-off for contributions. | 77 | Accepted | Make the repository carry durable understanding so agents remain disposable: source, schemas, tests, decisions, policies, indexes, and Evidence—not conversation memory—must re-orient a fresh contributor. See [ADR-0020](./adr/0020-repository-evidence-authorizes-agent-changes.md). |
| 78 | Accepted | Optimize agent-driven implementation in priority order: correctness, verified change, minimal unnecessary context/model calls/duplication, reproducible state, and efficient delegation. Measure tokens and total model cost per verified, accepted task rather than per call. |
| 79 | Accepted | Treat models as reasoning/generation engines. Prefer deterministic shell/code, then cheap retrieval/indexing, and invoke the cheapest model likely to complete the task only when semantic reasoning or generation is required. |
| 80 | Accepted | Keep root `AGENTS.md` a small always-loaded constitution; place conditional detail in versioned development policy and machine-readable configuration selected through progressive disclosure. |
| 81 | Accepted | Build `scripts/agent-context` as a tiny local context-compiler driver over current worktree state, task state, indexes, policy, and Evidence. Repository state is source, a provenance-bearing Context Graph is IR, and a stage-specific Orientation Packet is output. |
| 82 | Accepted | The context compiler never calls a model, guesses missing facts, or modifies authoritative project state. It may refresh derived indexes/caches and must expose missing, stale, or incomplete analysis explicitly. |
| 83 | Accepted | Prefer deltas and references over full-state copies, keep large logs outside model context, and disclose context in mandatory, relevant, and on-demand indexed layers without pruning required evidence for a token target. |
| 84 | Accepted | Treat every human or model as an untrusted Change Producer. Producer identity and self-reported success never grant merge authority; repository-owned verification does. See [ADR-0020](./adr/0020-repository-evidence-authorizes-agent-changes.md). |
| 85 | Accepted | Require every Candidate Change to pass distinct Specifier, Implementer, Cleaner, Hardener, source-blind QA, and deterministic-verifier responsibilities before integration. |
| 86 | Accepted | Mandate gauntlet stages, quality values, and deterministic exit criteria, but do not mandate a producer's private coding sequence when the resulting property can be verified objectively. |
| 87 | Accepted | Use CRAP/complexity analysis, architecture rules, mutation testing, coverage, property/fuzz tests, fault injection, and differential conformance as first-class quality evidence. Calibrate exact CRAP/mutation thresholds by package risk and implementation data; never allow silent survivors or exclusions. |
| 88 | Accepted | Keep QA source-blind: it receives public contracts, runnable artifacts, and user procedures rather than source or implementer rationale. A QA discovery becomes blocking through deterministic replay or explicit adjudication. |
| 89 | Accepted | Make handoffs reconstructible from a Work Item, exact repository state, and commit-bound structured Evidence. Subagents return concise results and artifact references rather than narratives or copied source/logs. |
| 90 | Accepted | Never recompute valid knowledge. Repeat work only after declared-input invalidation, loss of trusted Evidence, or to test a distinct failure model; machine-record the reason. |
| 91 | Accepted | Let a deterministic controller own retries, loop budgets, cancellation, and failure comparison. Repeated normalized failures stop blind repair and trigger assumption review, broader indexed context, or deliberate model/human escalation. |
| 92 | Accepted | Route work by total verified-task cost: use stronger reasoning when repeated weak-model failures would cost more, while keeping routine bounded generation on cheaper capable models. |
| 93 | Accepted | Never delegate mechanical work such as listing/searching/counting files, parsing data, running tools, inspecting exit codes, or comparing hashes. Delegate narrowly, depth-bound, and only for independent semantic reasoning or generation. |
| 94 | Accepted | Run parallel Work Items in isolated branches/worktrees with exact base revisions and atomic per-stage ownership. Never let concurrent agents share one mutable working directory or duplicate the same unchanged stage. |
| 95 | Accepted | Use contract-first parallelism: serialize unresolved changes to a shared protocol, schema, public API, or architectural Conflict Domain, integrate the contract, then fan out independent dependent work. |
| 96 | Accepted | Run an affected Candidate gauntlet before integration and an integration gauntlet over the combined state. Reuse fresh Evidence and rerun only invalidated dependency closures or genuinely whole-system checks. |
| 97 | Accepted | Protect the integration branch with trusted required checks and a merge queue or equivalent that verifies each Candidate against the latest target and preceding queued changes; agents cannot merge around failures. |
| 98 | Accepted | Use versioned deterministic analysis providers creatively: Git/compiler graphs for impact, ast-grep for tested structural policy, LSP for symbol/reference neighborhoods, CodeQL for deeper data flow, and purpose-built quality tools for tests and complexity. |
| 99 | Accepted | Treat quality as orthogonal evidence classes rather than CRAP, mutation, coverage, or one aggregate score alone: structure, test sensitivity, generated state/input space, cross-implementation conformance, public compatibility, runtime adversity, security/supply chain, performance/resources, evidence integrity, and source-blind product behavior. |
| 100 | Accepted | Require property-based, state-model, and fuzz testing—with reproducible seeds, minimized counterexamples, and regression corpora—for protocol graphs, Patches/selectors, configuration/provenance, framing, lifecycle, cancellation, and other invariant-heavy state machines. |
| 101 | Accepted | Make TypeScript/Go/native differential fixtures and API/schema compatibility reports mandatory for affected public contracts; neither mutation testing nor compile-time API comparison substitutes for behavioral conformance. |
| 102 | Accepted | Treat race detection, deterministic process/provider fault injection, termination/leak checks, CodeQL-style data-flow policy, reachable dependency vulnerability analysis, and versioned performance/resource budgets as first-class Evidence. |
| 103 | Accepted | Expose quality checks through replaceable Verifier Adapters registered with the repository tool-aware execution layer. Each declares applicability, inputs, output schema, cost class, cache key, invalidation, sensitivity, and stable finding codes. Tool/Verifier Adapters are not Meta Prompt Plugins and remain independent from the runtime under test. The repository verifier owns execution profiles, standard Harness Events/diagnostics, Evidence validation, and merge authority. |
| 104 | Accepted | Run quality lazily without weakening it: affected fast/Candidate checks first, invalidated integration closures next, and deliberately whole-system scheduled/release checks last. A strong result in one evidence class never compensates for a required failure or missing class. |
| 105 | Accepted | Adopt the repository operating principle verbatim: Reason with models; compute with tools; search structurally; store state externally; communicate through references; verify deterministically; retrieve progressively; delegate narrowly; automate repetition; measure everything. Measurement covers operational execution and outcomes, never private reasoning, secrets, or user content by default. See [ADR-0020](./adr/0020-repository-evidence-authorizes-agent-changes.md). |
| 106 | Accepted | Build a capability-first Tool Router rather than teaching every agent executable names and flags. It reuses fresh Evidence, then selects an applicable registered Automation Task or the cheapest trusted Tool Adapter before retrieval or model reasoning. See [tool-aware execution](./development/tool-aware-execution.md). |
| 107 | Accepted | Keep a curated machine-readable Tool Capability Registry with semantic operations, schemas, provider adapters, versions, platforms, effects/permissions, trust, execution/variance/delivery properties, cost/context classes, cache keys, and fallbacks. Expose only applicable capabilities to each agent. |
| 108 | Accepted | Record schema-validated operational Tool Traces—not private reasoning traces—with exact task/revision, normalized and resolved invocation, tool/config/input identity, effects, timing, exit/cache/failure data, raw and model-visible output sizes, redaction, and Evidence references. Raw output stays external and compact results communicate through references. |
| 109 | Accepted | Make the repository harness event-driven with standard Harness Events distinct from Meta Prompt runtime Events. Known events trigger revision-bound deterministic task graphs; models wake only for semantic work. Causation, idempotency, debounce/coalescing, locks, cancellation, budgets, and supersession prevent storms, duplication, and stale results. |
| 110 | Accepted | Add a read-only Automation Miner and explicit Automation Promotion Loop. Repeated normalized actions, subsequences, failures, reads, reductions, checks, or router bypasses produce referenced Automation Candidates; generated automation must pass the normal gauntlet and explicit registration and can never self-install or self-activate. |
| 111 | Accepted | Use one canonical, versioned Automation Task namespace consumed by humans, agents, watchers, and CI. Task runners and scripts are replaceable implementation details, not competing public authorities; each task declares schemas, effects, idempotency, dependencies/conflicts, budgets, cache/invalidation, Harness Events/diagnostics, Evidence, and tests. |
| 112 | Accepted | Measure routing, Evidence reuse, output/context reduction, runtime/resources, model calls and wakeups, repetition/duplication, automation lifecycle/cost, failure/flake/staleness, verification strength, accepted outcomes, rework, and escaped defects. Report “could have been deterministic” only as an auditable router miss or reviewed classification, and never optimize a metric by weakening correctness or privacy. |

## Documentation rule

When a decision changes, update this row and its linked design document in the same change. If an ADR is involved, create a new ADR that supersedes the old one rather than rewriting history.
