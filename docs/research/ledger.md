# Research ledger

This ledger records external patterns considered during phase 1 and the implementation-governance continuation. It is not an endorsement list. Each entry states the evidence, the transferable practice, and the current decision. Sources were last checked on **2026-08-26** unless noted.

Evidence levels:

- **Primary** — official specification or product documentation.
- **Implementation** — maintained project documentation or source describing actual behavior.
- **Practitioner** — first-person operating experience; useful for hypotheses and workflow design, but thresholds still require local measurement.
- **Market** — product positioning or feature documentation; useful for comparison, weaker as architectural proof.

## Prompt transformation and optimization

| System/source | Evidence | Relevant practice | Meta Prompt decision |
| --- | --- | --- | --- |
| [DSPy](https://dspy.ai/) | Implementation | Structured signatures separate task contracts from prompts; optimizers compile against examples and metrics. | Adopt the distinction between ordinary enhancement and empirical optimization. Defer optimizer Recipes until datasets and metrics exist. |
| [Anthropic Console prompting tools](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-tools) | Market | A dedicated tool can rewrite prompt templates, preserve variables, incorporate examples, and expose latency/cost trade-offs. | Bundle enhancement as a Recipe, but avoid tying the Artifact to one vendor or claiming universal improvement. |
| [OpenAI prompt optimizer](https://developers.openai.com/api/docs/guides/prompt-optimizer) | Market | Optimization is evaluation-driven and can improve or regress individual inputs. | Require eval gates and preserve reviewability; do not call a single rewrite “optimized.” |
| [Opik prompt optimization](https://www.comet.com/docs/opik/prompt_engineering/optimizer/overview) | Market | Prompt search is coupled to datasets, metrics, and evaluation loops. | Keep future optimization in replaceable evaluator/optimizer Plugins rather than Kernel behavior. |
| [Anthropic evaluation guidance](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests) | Primary | Evals should mirror the real task distribution and edge cases, use measurable multidimensional criteria, prefer deterministic grading where possible, and test model graders before scaling them. | Combine code checks, calibrated model graders, and human adjudication; do not collapse safety, fidelity, utility, latency, and cost into one number. |
| [NIST AI 800-3](https://doi.org/10.6028/NIST.AI.800-3) | Primary | Benchmark accuracy and generalized performance are different claims, and uncertainty estimates depend on explicit assumptions about items and repeated trials. | Publish fixed-corpus results as such, use paired bootstrap intervals for downstream comparisons, and avoid universal quality claims from one finite benchmark. |
| [NIST AITE](https://www.nist.gov/news-events/news/2026/07/announcing-nists-artificial-intelligence-technology-evaluation-aite) | Primary | Sequestered evaluation data reduces test contamination and preserves an objective release check. | Keep a rotating holdout unavailable to strategy authoring until release, then publish it for audit and replace it for the next release. |

| [JSON-RPC 2.0](https://www.jsonrpc.org/specification) | Primary | Requests, responses, notifications, and protocol errors have a small transport-neutral model. | Use JSON-RPC for process communication; reserve its error object for RPC/protocol faults. |

| [OpenAI Responses inputs](https://developers.openai.com/api/reference/cli/resources/responses/methods/create) | Primary | Model APIs may accept text, image, or file inputs, but support belongs to the selected model/provider contract. | Keep the Kernel text-first and expose non-text support through Provider and modality capabilities. |

| [llama.cpp HTTP server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) | Implementation | The server offers Chat Completions, Responses, streaming, structured output, and extensions, while explicitly avoiding a strong compatibility claim and conditioning behavior on model templates. | Use a minimal baseline and evidence-backed optional capabilities; preserve provider-specific options only in its namespace. |
| [LocalAI text generation](https://localai.io/docs/features/text-generation/) | Implementation | A common OpenAI-shaped route spans different inference backends and documents a smaller common text parameter set. | Treat the server and selected model/backend as one capability target rather than attaching permanent features to the LocalAI brand. |
| [Claude PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support) | Primary | PDFs may require both text extraction and visual analysis and have model/platform-specific limits and costs. | Treat PDF interpretation as Plugin behavior rather than a universal Prompt Document obligation. |
| [GitHub Copilot image input](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/image-input) | Primary | Hosts distinguish file/blob attachment mechanisms and gate images on model vision capability. | Require explicit Host attachment and capability negotiation; never silently drop unsupported resources. |
| [RFC 6902 JSON Patch](https://www.rfc-editor.org/info/rfc6902/) | Primary | Ordered atomic operations and test preconditions are portable, but paths address generic JSON structure and array positions. | Adapt atomicity and preconditions; replace JSON Pointer with stable domain identities and typed operations. |
| [Kubernetes patch behavior](https://kubernetes.io/docs/tasks/manage-kubernetes-objects/update-api-object-kubectl-patch/) | Primary | Generic merge semantics are insufficient for every list, leading to schema-aware patch strategies and merge keys. | Define Prompt Document operations explicitly instead of relying on one generic merge algorithm. |
| [Language Server Protocol](https://microsoft.github.io/language-server-protocol/) | Primary | Cross-language editors use domain-specific, version-aware text document operations over JSON-RPC. | Carry base revision and target identity in portable Patch envelopes. |
| [W3C Web Annotation text selectors](https://w3c.github.io/web-annotation/model/wd2/) | Primary | Exact text identity and positional selection solve a different problem from meaning-level validation; positions alone are brittle after edits. | Make exact identity Kernel-enforceable and keep semantic preservation in Guard policy. |
| [Kubernetes admission control](https://kubernetes.io/docs/reference/access-authn-authz/admission-controllers/) | Primary | Mutation and final read-only policy validation have distinct lifecycle semantics. | Reject exact-span overlap mechanically and evaluate Semantic Constraints through `validate` Guard nodes. |
| [Unicode text segmentation](https://www.unicode.org/reports/tr29/) | Primary | Code points and user-perceived grapheme clusters are different; valid editing boundaries require defined segmentation. | Count portable ranges in Unicode scalar values and reject endpoints inside extended grapheme clusters. |
| [CloudEvents specification](https://github.com/cloudevents/spec/blob/main/cloudevents/spec.md) | Primary | Generic envelopes separate semantic type, content type, schema identity, source, and payload. | Use distinct Artifact kind, media type, data schema, identity, and provenance fields. |
| [OCI content descriptors](https://github.com/opencontainers/image-spec/blob/main/descriptor.md) | Primary | Media type, digest, size, and reference metadata make external content verifiable without embedding it. | Permit Resource Reference Artifact values and verify digests; do not embed arbitrary binary values. |
| [W3C PROV primer](https://www.w3.org/TR/prov-primer/) | Primary | Provenance relates generated entities to activities, agents, and source entities. | Record compact producer, invocation, parent, Patch, and model-call relationships without adopting the full ontology. |
| [MCP tool results](https://modelcontextprotocol.io/specification/2025-06-18/schema) | Primary | Operational tool failure belongs in a typed result, while protocol faults remain protocol errors. | Keep ordinary Run outcomes and safe Diagnostics in `RunResult`, not JSON-RPC errors. |
| [OpenTelemetry log data model](https://opentelemetry.io/docs/specs/otel/logs/data-model/) | Primary | Events carry time, trace context, severity, named semantics, attributes, and body while exception attributes may be sensitive. | Use a correlated standard envelope and keep exception details in Debug Records. |
| [OpenTelemetry error handling](https://opentelemetry.io/docs/specs/otel/error-handling/) | Primary | Optional observers/exporters must not alter application behavior and should expose self-diagnostics. | Isolate observer queues, drop progress first, detach unhealthy observers, and report through healthy observers. |
| [RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457.html) | Primary | Stable machine-readable problem identity should be separate from unsafe implementation debugging details. | Make Diagnostic codes stable and portable while keeping exception messages/stacks out of normal Results. |
| [gRPC message limits](https://grpc.github.io/grpc/cpp/group__grpc__arg__keys.html) | Primary | A finite default receive limit protects processes that have not planned for arbitrarily large messages. | Negotiate bounded JSON frames and use Resource References for large content instead of unlimited payloads. |
| [LSP-style cancellation](https://microsoft.github.io/vs-streamjsonrpc/docs/sendrequest.html) | Implementation | JSON-RPC cancellation is a cooperative notification and may need transport/process fallback. | Send cancellation first, then enforce a short supervisor grace period. |
| [Node child processes](https://nodejs.org/api/child_process.html) | Primary | stdout/stderr pipes have finite capacity and must be drained; shell execution with untrusted input is unsafe. | Drain bounded stderr continuously and spawn explicit commands without a shell. |
| [Kubernetes process termination](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/#pod-termination) | Primary | Graceful termination followed by a bounded force-kill ensures shutdown eventually completes. | Apply cooperative shutdown, graceful termination, and final force-kill stages with normalized outcomes. |
| [JSON Schema 2020-12](https://json-schema.org/draft/2020-12) | Primary | A language-neutral schema vocabulary can define portable wire contracts. | Make a constrained 2020-12 profile authoritative across TypeScript and Go. |
| [Ajv strict mode](https://ajv.js.org/strict-mode.html) | Implementation | Strict compilation prevents ignored or ambiguous schema constructs. | Compile schemas strictly and reject unknown constructs. |
| [Ajv data modification](https://ajv.js.org/guide/modifying-data.html) | Implementation | Coercion/default insertion/removal makes validation impure and order-sensitive. | Disable mutation; resolve defaults/configuration separately with provenance. |
| [JSON Schema Test Suite](https://github.com/json-schema-org/JSON-Schema-Test-Suite) | Implementation | Language-neutral fixtures expose validator differences across released dialects. | Run applicable official cases plus project-specific differential fixtures in Node and Go. |
| [Bowtie](https://docs.bowtie.report/en/latest/) | Implementation | A common harness compares JSON Schema implementations and dialect support. | Use reports as ecosystem evidence while keeping Meta Prompt's constrained profile and fixtures authoritative. |
| [santhosh-tekuri/jsonschema v6](https://github.com/santhosh-tekuri/jsonschema) | Implementation | The Go validator supports Draft 2020-12, formats, custom registries, and official-suite compatibility. | Adopt it for Go protocol validation, pinned and exercised by shared fixtures. |

## Research rules going forward

For every major unresolved problem:

1. Prefer official specifications and primary documentation.
2. Record the concrete problem the source solves, not just the product name.
3. Separate vendor-specific behavior from transferable design practice.
4. State adopt, adapt, reject, or defer and why.
5. Verify Host and library behavior again before implementation because APIs change.
6. Add the source date and evidence level; do not turn an old link into an eternal claim.
